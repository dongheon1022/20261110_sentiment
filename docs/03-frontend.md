# 03. 프런트엔드 구현

## 담당 범위

- `public/index.html`: 접근 가능한 시맨틱 화면 구조
- `public/css/style.css`: 디자인 토큰, 레이아웃, 반응형 스타일
- `public/js/app.js`: 입력 검증, API 요청, 상태 및 결과 렌더링

## 화면 상태

프런트엔드는 다음 상태를 명확히 관리한다.

| 상태 | 화면 동작 |
|---|---|
| `idle` | 입력 가능, 기본 안내 표시 |
| `loading` | 버튼 비활성화, 진행 중 안내 표시 |
| `success` | 감정·신뢰도·이유 표시 |
| `error` | 사용자용 오류 메시지 표시, 재시도 가능 |

상태를 중복된 boolean 여러 개로 관리해 서로 모순되는 화면이 나오지 않도록 한다. 단일 상태 값 또는 일관된 상태 객체를 사용한다.

## 입력 검증

- `textarea`의 앞뒤 공백을 제거한 문자열을 전송한다.
- 빈 문자열은 요청하지 않는다.
- 5,000자를 초과하면 요청하지 않는다.
- 글자 수는 사용자가 이해할 수 있게 실시간 표시한다.
- Enter 키는 줄바꿈으로 동작한다. 제출은 버튼 또는 명시적인 키보드 조작으로 한다.

## API 통신

요청:

```http
POST /api/analyze
Content-Type: application/json

{
  "text": "오늘은 정말 기분 좋은 하루였다."
}
```

성공 응답:

```json
{
  "success": true,
  "data": {
    "sentiment": "positive",
    "confidence": 92,
    "reasons": [
      "기분이 좋았다는 긍정적인 표현이 포함되어 있습니다."
    ]
  },
  "saved": true
}
```

저장 실패 시에도 분석은 성공할 수 있다.

```json
{
  "success": true,
  "data": {
    "sentiment": "neutral",
    "confidence": 71,
    "reasons": ["뚜렷한 긍정 또는 부정 표현이 적습니다."]
  },
  "saved": false,
  "warning": "분석 결과를 저장하지 못했습니다."
}
```

실패 응답 예:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "분석할 텍스트를 1~5,000자로 입력해 주세요."
  }
}
```

## 결과 렌더링

- 서버 응답의 `sentiment`를 허용된 세 값과 대조한다.
- 라벨은 한국어로 변환해 표시한다.
- 신뢰도는 `0%`~`100%` 범위로 표시한다.
- `reasons` 배열의 항목을 목록으로 표시한다.
- 모든 사용자 입력과 AI 생성 텍스트는 `textContent`로 넣는다. `innerHTML`로 삽입하지 않는다.
- `saved: false`면 결과는 유지하면서 별도의 저장 경고를 표시한다.

## 오류 처리

- 네트워크 오류: `연결이 원활하지 않습니다. 잠시 후 다시 시도해 주세요.`
- 서버 오류: `분석 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요.`
- 입력 오류: 서버가 반환한 안전한 검증 메시지를 표시한다.
- 응답 JSON 파싱 실패: 일반 오류로 처리한다.
- 오류 후 버튼을 다시 활성화한다.

## 접근성

- 입력창에 `label`을 연결한다.
- 결과 영역은 적절한 `aria-live`를 사용해 변경 내용을 알린다.
- 포커스 표시를 제거하지 않는다.
- 버튼은 실제 `<button>` 요소를 사용한다.

## 완료 기준

- 정상 입력 시 결과가 화면에 표시된다.
- 빠르게 버튼을 여러 번 눌러도 중복 요청이 발생하지 않는다.
- 모든 오류에서 입력 내용이 사라지지 않고 재시도할 수 있다.
- 스크린 리더와 키보드 사용을 막는 구조가 없다.
