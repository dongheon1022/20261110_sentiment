# 06. 배포 및 검증

## 1. 로컬 실행

1. Node.js LTS 설치를 확인한다.
2. 프로젝트 루트에서 `npm install`을 실행한다.
3. `.env.example`을 참고해 `.env`를 만들고 실제 키를 입력한다.
4. Supabase SQL Editor에서 `docs/05-ai-and-database.md`의 테이블 SQL을 실행한다.
5. `npm run dev` 등 `package.json`에 정의한 개발 명령으로 실행한다.
6. 브라우저에서 로컬 페이지를 열고 API 요청을 확인한다.

실제 스크립트 이름은 `package.json`에 정의된 값과 문서가 일치해야 한다. 구현하지 않은 스크립트를 실행 방법에 적지 않는다.

## 2. Vercel 배포

1. Git 저장소에 프로젝트를 커밋한다. `.env`는 커밋하지 않는다.
2. Vercel에서 저장소를 연결한다.
3. 프레임워크 자동 감지가 정적 사이트 + Node.js Functions 구조와 맞는지 확인한다.
4. Vercel 프로젝트 설정의 Environment Variables에 아래 값을 등록한다.
   - `OPENAI_API_KEY`
   - `OPENAI_MODEL`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
5. Production, Preview, Development 환경 중 실제 사용하는 환경에 각각 필요한 변수를 설정한다.
6. 배포 후 `/`와 `/api/analyze`를 확인한다.
7. 환경 변수를 변경했다면 새 배포를 수행한다.

| T-12 | 모바일 375px 화면 | 가로 스크롤 없이 입력·결과 확인 가능 |

## 4. 배포 전 체크리스트

- [ ] 환경 변수 4개가 Vercel에 설정되어 있다.
- [ ] API 키와 service role 키가 프런트엔드에 없다.
- [ ] Supabase 테이블과 RLS가 준비되어 있다.
- [ ] 저장 안내 문구가 사용자에게 보인다.
- [ ] 정상 분석과 저장이 실제 배포 주소에서 확인된다.
- [ ] DB 저장 실패 시 분석 결과가 유지된다.
- [ ] 모바일 및 데스크톱 레이아웃을 확인했다.
- [ ] 오류 응답에 스택 트레이스나 비밀 정보가 없다.
- [ ] 브라우저 콘솔과 Vercel 로그에 불필요한 원문/키가 남지 않는다.
- [ ] 개인정보 보존·삭제 정책을 운영자가 확인했다.

## 5. 완료 보고 형식

에이전트는 작업 후 아래 항목을 보고한다.

1. 구현한 기능

6. Vercel 배포 여부 및 배포 전 남은 작업
7. 미구현 또는 운영자 결정이 필요한 사항
