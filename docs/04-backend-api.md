# 04. 백엔드 API 구현

## API 명세

| 항목 | 값 |
|---|---|
| 메서드 | `POST` |
| 경로 | `/api/analyze` |
| 요청 형식 | JSON |
| 요청 필드 | `text: string` |
| 최대 입력 | 5,000자 |
| 성공 상태 | HTTP 200 |
| 잘못된 입력 | HTTP 400 |
| 설정 누락 | HTTP 500 |
| 외부 AI 오류 | HTTP 502 또는 적절한 서버 오류 |

## 서버 처리 순서

1. 요청 메서드가 POST인지 확인한다.
2. Content-Type과 JSON 본문을 확인한다.
3. `text`가 문자열인지 확인한다.
4. 앞뒤 공백을 제거하고 1~5,000자인지 검사한다.
5. 서버 환경 변수에 OpenAI 키와 Supabase 설정이 있는지 확인한다.
6. OpenAI 분석 함수를 호출한다.
7. AI 응답을 파싱하고 허용 스키마인지 검증한다.
8. Supabase `analyses` 테이블에 저장을 시도한다.
9. 분석 결과와 저장 여부를 JSON으로 반환한다.

## 응답 스키마

성공:

```json
{
  "success": true,
  "data": {
    "sentiment": "positive",
    "confidence": 85,
    "reasons": ["긍정적인 평가 표현이 사용되었습니다."]
  },
  "saved": true
}
```

오류:

```json
{
  "success": false,
  "error": {
    "code": "AI_SERVICE_ERROR",
    "message": "분석 서비스를 일시적으로 사용할 수 없습니다."
  }
}
```

## 오류 코드

| 코드 | 의미 | 사용자 안내 |
|---|---|---|
| `METHOD_NOT_ALLOWED` | POST 외 메서드 | 지원하지 않는 요청입니다. |
| `VALIDATION_ERROR` | 입력 누락·길이 초과 | 1~5,000자 텍스트를 입력해 주세요. |
| `CONFIGURATION_ERROR` | 서버 환경 변수 누락 | 서비스 설정 오류입니다. 잠시 후 다시 시도해 주세요. |
| `AI_SERVICE_ERROR` | OpenAI 호출 실패 | 분석 서비스를 일시적으로 사용할 수 없습니다. |
| `AI_RESPONSE_INVALID` | AI 응답 형식 오류 | 분석 결과를 처리하지 못했습니다. 다시 시도해 주세요. |
| `INTERNAL_ERROR` | 예상하지 못한 오류 | 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. |

## 보안 및 운영 규칙

- 키는 `process.env`에서만 읽는다.
- `service_role` 키를 클라이언트에 노출하지 않는다.
- 원문, API 키, 공급자 응답 전문을 서버 로그에 출력하지 않는다.
- 사용자에게 내부 오류 메시지와 스택을 반환하지 않는다.
- 입력 크기와 요청 빈도를 제한할 수 있도록 서버 구조를 작성한다. MVP에서 별도 요금제나 복잡한 레이트 리밋 시스템은 추가하지 않는다.
- CORS를 전체 공개로 설정할 필요가 없다. 동일 출처 호출을 기본으로 한다.

## 저장 실패 정책

분석 결과가 유효하면 DB 저장 실패만으로 분석을 실패 처리하지 않는다. `saved: false`와 `warning`을 반환하고 결과를 사용자에게 표시한다. 저장 오류의 상세 내용은 서버 로그에 민감 정보 없이 기록한다.

## 완료 기준

- 명세에 맞는 성공·오류 JSON을 반환한다.
- 잘못된 메서드와 입력을 거부한다.
- OpenAI 오류와 잘못된 응답을 안전하게 처리한다.
- 서버 비밀 키가 브라우저 번들 또는 응답에 포함되지 않는다.
